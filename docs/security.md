# 安全设计文档

本文记录光阶Todo账号、同步、设备和后台管理相关的安全设计要求。客户端是本地优先应用，安全重点是保护账号凭据、邮箱验证、云端同步数据和远程设备管理能力。

## 1. 账号与密码

- 用户使用邮箱 + 密码注册登录。
- 密码只保存 Argon2 哈希，不保存明文。
- 登录失败时不要区分“邮箱不存在”和“密码错误”，避免账号枚举。
- 密码长度、复杂度和弱密码检查应在前端友好提示，后端继续做兜底校验。
- 管理员账号和普通用户账号使用同一登录机制，但后台接口必须校验管理员角色。

## 2. 邮箱验证

邮箱验证用于决定账号是否可以启用云端同步。

- 验证码只保存哈希。
- 验证码必须有过期时间。
- 同一邮箱和同一 IP 必须有发送频率限制。
- 验证码输入限制 6 位。
- 未验证邮箱的账号允许本地使用，但不能同步。
- 验证成功后立即刷新用户资料和同步状态。

前端提示必须面向用户，不展示 SMTP、HTTP 状态码或后端内部错误。

## 3. Token

- access token 短期有效，默认 15 分钟。
- refresh token 长期有效，默认 30 天。
- refresh token 在服务端只保存哈希。
- 退出登录、移除设备、移除其他设备时必须撤销对应 refresh token。
- 客户端收到未授权错误时，应先尝试刷新 token；刷新失败再引导用户重新登录。

## 4. 设备安全

每次登录都会绑定设备信息：

- 设备 ID。
- 设备指纹。
- 设备名称。
- 平台信息。
- 客户端版本号。
- 最近登录时间。
- 最近同步时间。

设备被远程移除后：

- 后端立即拒绝该设备继续刷新 token 或同步。
- 如果用户请求清理，后端记录 `wipe_requested_at`。
- 旧设备下次联网时执行本地清理，并回写 `wiped_at`。

远程清理无法保证离线设备立即删除数据，UI 必须明确表达“下次联网清理”的含义。

## 5. 云同步数据

- 同步接口必须要求登录态。
- 未验证邮箱不能上传或拉取同步快照。
- 同步快照按用户隔离，任何接口都不能通过客户端传入的用户 ID 跨账号访问。
- 快照上传必须记录设备 ID、客户端版本、数据大小和结果状态。
- 冲突时返回明确错误码，客户端执行拉取和合并，不让用户直接面对技术错误。

头像不参与同步，避免把本地图片隐私数据自动上传。

## 6. 管理后台

后台系统用于查看系统运行情况和产品运营情况，不应成为高风险操作入口。

要求：

- 所有 `/api/admin/*` 接口必须校验管理员角色。
- 登录失败提示保持模糊，不泄露账号是否存在。
- 用户详情、设备、同步日志只展示必要信息。
- 不在后台展示密码哈希、refresh token 哈希、验证码哈希。
- 高风险操作后续需要审计日志。
- 生产环境建议增加二次验证和访问来源限制。

## 7. 敏感配置

禁止提交到仓库：

- SMTP 授权码。
- 生产数据库密码。
- 生产 `JWT_SECRET`。
- 管理员真实密码。
- 第三方 OAuth client secret。

建议：

- 使用 `.env` 管理本地开发配置。
- 生产环境使用平台密钥管理。
- 定期轮换 SMTP 授权码和管理员密码。
- 日志中屏蔽 token、验证码、密码和邮箱授权信息。

## 8. 客户端本地数据

客户端本地数据目录通常位于：

```text
%APPDATA%\com.ascend.todo
```

安全要求：

- 退出并清理这台电脑时删除当前账号业务数据和登录态。
- 卸载时清理本地数据，避免重装后仍保持登录状态。
- 本地错误日志不记录密码、验证码和 token。
- 示例数据只在首次安装且没有用户数据时生成。

## 9. 错误提示策略

普通用户不应看到：

```text
UNAUTHORIZED
BAD_REQUEST
invalid: {...}
auth error: ...
SQL error
SMTP error
```

推荐提示：

- 登录已过期，请重新登录。
- 验证码发送太频繁，请稍后再试。
- 邮箱验证后才能同步。
- 网络连接失败，请检查网络后重试。
- 当前设备已被移除，无法继续同步。

## 10. 安全验证清单

- 注册、登录、刷新 token、退出登录均正常。
- 未验证邮箱无法同步。
- 验证码过期后无法使用。
- 短时间重复发送验证码会被限制。
- 移除设备后该设备无法继续同步。
- 当前设备不会显示移除按钮。
- 退出并清理这台电脑后，本地账号数据被清理。
- 管理员接口普通用户无法访问。
- 日志中没有密码、token、验证码明文。
