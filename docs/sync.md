# 云同步设计

本文说明光阶Todo客户端与云端之间的数据同步模型。当前同步策略是本地优先、账号隔离、快照同步，目标是在网络不稳定或用户更换设备时尽量保护本地数据，并让用户清楚知道每一次登录、退出和清理操作的结果。

## 1. 同步目标

- 用户可以在多台设备之间同步任务、目标、日历、番茄钟记录、设置和个人资料文字信息。
- 用户未验证邮箱前可以正常本地使用，但不能启用云端同步。
- 用户退出登录时可以选择保留本机数据或清理本机数据。
- 设备被远程移除后，立即失去云端访问能力；如果用户请求清理旧设备，则旧设备下次联网时执行本地清理。
- 头像不参与同步，每台设备可以独立显示本地头像。

## 2. 同步前置条件

客户端只有同时满足以下条件才允许同步：

1. 用户已登录。
2. 邮箱已验证。
3. 当前设备未被撤销。
4. 当前用户状态为 `active`。
5. 用户开启了云端同步。
6. 后端服务可访问，access token 可用或 refresh token 可刷新。

任一条件不满足时，客户端应使用用户能理解的提示，例如“邮箱验证后才能同步”“当前设备已被移除，请重新登录”，不要直接展示后端原始错误。

## 3. 同步范围

参与同步：

- 任务看板、列表、任务卡片、任务详情、任务描述。
- 目标、关键结果、进度记录。
- 日历日程、任务安排、节假日日历选择。
- 番茄钟计划、专注记录、统计数据。
- 软件设置中需要跨设备一致的配置。
- 昵称、个性签名等个人资料文字信息。

不参与同步：

- 用户头像。
- 邮箱授权 token、OAuth 授权缓存。
- 本地安装包缓存、更新缓存。
- 本机窗口位置、临时 UI 状态。
- 本地日志、数据库文件路径、设备指纹。

## 4. 账号与本地数据关系

客户端是本地优先应用，本地 SQLite 数据始终是当前设备的主要工作数据源。

- 未登录：数据只保存在本机。
- 已登录但未验证邮箱：数据仍只保存在本机。
- 已登录且验证邮箱：允许上传本地快照，也允许从云端拉取快照。
- 退出并保留本机数据：只清理登录态，数据仍留在当前电脑。
- 退出并清理这台电脑：清理当前账号在本机的业务数据、登录态和缓存。

如果用户在一台临时设备登录后又把设备交给别人，推荐操作是进入个人资料页的登录设备列表，移除该设备并请求清理。远程清理不是实时保证，只有旧设备再次联网并启动客户端后才能执行本地清理。

## 5. 快照模型

后端保存每个用户的一份云端快照，快照带有递增版本号。

客户端上传字段：

```json
{
  "snapshot": {},
  "localVersion": 12,
  "baseRemoteVersion": 5,
  "clientVersion": "1.0.0"
}
```

后端拉取返回：

```json
{
  "snapshot": {},
  "version": 6,
  "updatedAt": "2026-07-07T10:30:00"
}
```

`baseRemoteVersion` 是客户端上次知道的云端版本，用来判断上传时云端是否已被其他设备改写。

## 6. 冲突处理

推荐客户端流程：

1. 同步前读取本地快照和本地已知的 `remoteVersion`。
2. 调用 `POST /api/sync/push-snapshot`。
3. 如果成功，保存新的云端版本号。
4. 如果返回 `409 CONFLICT`，先调用 `GET /api/sync/pull-snapshot` 拉取云端数据。
5. 用记录 ID、更新时间和删除标记执行智能合并。
6. 合并结果写回本地，再重新上传云端。

合并规则建议：

- 同一条记录两端都存在时，选择 `updatedAt` 更新的一份。
- 本地有云端没有的新记录，保留本地记录。
- 云端有本地没有的新记录，写入本地。
- 删除记录需要保留删除标记，避免另一端把已删除数据恢复出来。
- 设置类数据以更近一次修改为准；如果缺少修改时间，则以当前设备为准补齐。

## 7. 触发同步

客户端建议在以下时机触发同步：

- 登录成功且邮箱已验证后，立即拉取云端数据。
- 用户开启云端同步后，立即执行一次完整同步。
- 本地关键数据修改后，进行防抖同步。
- 应用启动、窗口重新获得焦点、网络恢复后，执行增量检查。
- 用户点击手动同步时，立即同步并显示结果。
- 退出登录前，检查是否存在未同步数据。

同步执行必须避免阻塞主界面。耗时操作应在后台执行，UI 只显示轻量状态。

## 8. 退出登录

退出登录弹窗使用选择卡片，不让用户输入文字确认。

选项建议：

- 仅退出账号：清理 token 和当前会话，本机业务数据保留。
- 退出并清理这台电脑：清理当前账号在本机的数据、token、同步状态和缓存。

执行前：

1. 如果云端同步可用，先尝试上传最新数据。
2. 如果上传失败，明确提示用户“有数据尚未同步，继续退出可能只保留在本机”。
3. 用户确认后再执行退出。

## 9. 设备管理

个人资料页展示当前账号的登录设备。

- 当前设备：不显示移除按钮。
- 其他设备：可重命名、移除、请求下次联网清理。
- 被移除设备：列表中应实时刷新状态，避免用户误以为移除失败。
- 请求清理后：显示清理请求状态，旧设备完成清理后显示已清理。

后端接口：

```text
GET    /api/devices
PATCH  /api/devices/{id}
DELETE /api/devices/{id}
POST   /api/devices/revoke-others
POST   /api/devices/{id}/request-wipe
POST   /api/devices/{id}/mark-wiped
```

## 10. 错误提示

禁止把以下原始错误直接显示给普通用户：

```text
invalid: {"code":"UNAUTHORIZED","message":"unauthorized"}
auth error: ...
```

客户端需要转换为用户可理解的提示：

- 登录已过期，请重新登录。
- 邮箱验证后才能同步。
- 网络连接失败，请稍后重试。
- 当前设备已被移除，无法继续同步。
- 云端数据已更新，正在合并后重试。

## 11. 验证清单

- 未登录时不触发云端同步。
- 未验证邮箱时无法开启同步。
- 验证邮箱后默认开启云端同步。
- A 设备创建数据后，B 设备登录能拉取数据。
- B 设备修改后，A 设备能合并更新。
- 退出并保留本机数据后，重新登录仍可看到本地数据。
- 退出并清理这台电脑后，重新登录会从云端拉取数据。
- 远程移除其他设备后，对应设备无法继续同步。
- 头像在不同设备之间不会同步。
