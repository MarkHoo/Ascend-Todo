# 桌面端账号与云同步接入契约

本文档定义桌面客户端接入账号、邮箱验证、云同步和设备管理时必须遵守的行为。当前桌面端目录结构保持不变，后续只在现有页面中增加账号与同步入口。

## 1. 本地优先原则

1. 用户未登录时，所有本地功能继续可用。
2. 用户已登录但邮箱未验证时，所有本地功能继续可用，但同步入口必须显示“验证邮箱后开启同步”。
3. 任何网络错误都不能阻塞应用启动、任务编辑、日历查看、番茄钟运行等本地功能。
4. 后台同步失败只显示轻量状态，不弹出阻断式窗口。

## 2. 客户端状态

桌面端需要维护以下账号状态：

```text
anonymous
logged_in_unverified
logged_in_verified
syncing
sync_failed
device_revoked
wipe_requested
```

状态含义：

- `anonymous`：未登录，只使用本地数据。
- `logged_in_unverified`：已登录，邮箱未验证，不允许同步。
- `logged_in_verified`：已登录且邮箱已验证，可以同步。
- `syncing`：正在上传或拉取快照。
- `sync_failed`：最近一次同步失败，但本地功能继续可用。
- `device_revoked`：当前设备授权已被移除，停止同步并提示重新登录。
- `wipe_requested`：服务端要求此设备清理本地数据，必须先让用户确认当前操作。

## 3. 登录后的数据处理

### 3.1 本机无数据，云端有数据

自动拉取云端快照并恢复到本地，恢复前创建本地备份点。

### 3.2 本机有数据，云端无数据

提示用户：

```text
是否将本机数据上传到云端？
- 上传本机数据
- 暂不上传，仅本机使用
```

邮箱未验证时不允许上传。

### 3.3 本机有数据，云端也有数据

必须让用户选择：

```text
选择同步方式
- 合并本机与云端数据
- 使用云端数据覆盖本机
- 使用本机数据覆盖云端
- 取消，仅本机使用
```

覆盖类操作必须二次确认，并在操作前创建本地备份点。

## 4. 同步触发

允许触发同步的场景：

1. 应用启动后，账号已登录且邮箱已验证。
2. 用户手动点击同步。
3. 本地关键数据变更后进入防抖队列。
4. 应用从后台恢复到前台。
5. 网络从离线恢复到在线。
6. 退出登录前发现存在未同步数据。

推荐节流：

- 本地变更后 5 秒防抖上传。
- 前台自动同步间隔 1 分钟。
- 后台自动同步间隔 5 分钟。
- 连续失败后使用指数退避，最大 30 分钟。

## 5. 退出登录

退出登录前必须检查是否存在未同步数据。

如果存在未同步数据且邮箱已验证：

```text
当前有未同步数据，请选择：
- 立即同步后退出
- 不同步，仅退出账号并保留本机数据
- 取消
```

如果用户选择“退出并清除此设备数据”，必须二次确认。

默认退出只清除 token，不删除本机数据。

## 6. 远程移除设备

远程移除设备只保证撤销云端访问能力。旧设备如果已经离线，无法保证立即清除它的本地数据。

旧设备下一次联网时：

1. 请求任意云同步接口。
2. 服务端返回设备已撤销或要求清理。
3. 客户端停止同步。
4. 如果存在 `wipe_requested`，提示用户执行本机数据清理。
5. 清理成功后回写 `wiped_at`。

## 7. 不同步内容

以下内容永远不进入云端同步：

- 头像图片。
- 邮箱会议 OAuth token。
- 邮箱会议本机凭据。
- 本机缓存。
- 更新安装包缓存。
- 本机日志。
- 本机路径。

## 8. 推荐客户端新增文件

后续接入桌面端时，建议只在现有结构下新增这些文件：

```text
src/api/cloudAuth.ts
src/api/cloudSync.ts
src/api/cloudDevices.ts
src/store/useCloudAccountStore.ts
src/store/useCloudSyncStore.ts
src/utils/cloudSnapshot.ts
src/utils/localBackup.ts
src/components/settings/CloudAccountSection.tsx
src/components/settings/DeviceManagerSection.tsx
```

现有业务模块只通过 store 和 api 层调用云同步能力，避免同步逻辑散落到任务、日历、目标等页面里。
