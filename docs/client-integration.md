# 客户端账号与云同步接入文档

本文定义桌面客户端接入账号、邮箱验证、云同步和设备管理时必须遵守的行为。

## 1. 本地优先原则

1. 未登录时，所有本地功能必须可用。
2. 已登录但邮箱未验证时，本地功能继续可用，但同步入口必须提示“验证邮箱后才能同步”。
3. 网络错误不能阻塞应用启动、任务编辑、日历查看或番茄钟运行。
4. 后台自动同步失败时，只显示轻量提示，不弹出阻断式窗口。

## 2. 客户端账号状态

客户端需要维护以下状态：

```text
anonymous
logged_in_unverified
logged_in_verified
syncing
sync_failed
device_revoked
wipe_requested
```

含义：

- `anonymous`：未登录，只使用本地数据。
- `logged_in_unverified`：已登录，邮箱未验证，不允许同步。
- `logged_in_verified`：已登录且邮箱已验证，可以同步。
- `syncing`：正在推送、拉取或合并数据。
- `sync_failed`：最近一次同步失败，但本地功能继续可用。
- `device_revoked`：当前设备授权已被移除，需要重新登录。
- `wipe_requested`：服务端要求当前设备清理本地数据。

## 3. 登录后的数据处理

### 本机无数据，云端有数据

自动拉取云端快照并恢复到本地。恢复前创建安全备份。

### 本机有数据，云端无数据

提示用户选择：

```text
是否将本机数据上传到云端？
- 上传本机数据
- 暂不上传，仅本机使用
```

邮箱未验证时禁止上传。

### 本机有数据，云端也有数据

必须让用户选择：

```text
选择同步方式
- 合并本机与云端数据
- 使用云端数据恢复本机
- 使用本机数据覆盖云端
- 暂时跳过
```

覆盖类操作必须在执行前创建本地备份。

## 4. 自动同步触发

允许触发同步的场景：

1. 应用启动后，账号已登录且邮箱已验证。
2. 用户手动点击同步。
3. 本地关键数据变更后进入防抖队列。
4. 应用从后台恢复到前台。
5. 网络从离线恢复到在线。
6. 退出登录前发现存在未同步数据。

当前建议：

- 启动后延迟同步，避免影响首屏。
- 前台定时同步。
- 后台低频同步。
- 连续失败后使用退避策略。

## 5. 退出登录

退出登录前必须检查是否存在未同步数据。

推荐选项：

```text
退出前如何处理这台设备的数据？
- 同步后退出
- 退出并保留本机数据
- 退出并清理这台电脑
```

说明：

- 默认退出只清理账号 token，不删除本地数据。
- 用户明确选择清理本机数据时，必须先创建安全备份。
- 清理成功后再移除会话状态。

## 6. 设备管理

设备列表应实时刷新处理后的状态。

当前设备：

- 可以重命名。
- 不显示移除按钮。
- 不显示请求清理按钮。

其他设备：

- 可移除。
- 可请求下次联网时清理本地数据。

远程移除只能保证撤销云端访问能力。离线设备无法立即清理本地数据，必须等下次联网后执行。

## 7. 不同步内容

以下内容永远不进入云同步：

- 头像图片。
- 邮箱会议 OAuth token。
- 邮箱会议本地凭据。
- 本地缓存。
- 更新安装包缓存。
- 本地日志。
- 本机路径。

## 8. 错误提示规范

禁止直接向用户显示：

- 原始 HTTP JSON。
- Rust 内部错误。
- `UNAUTHORIZED`、`invalid` 等技术错误。

必须转换为用户可理解的文案，例如：

- 登录状态已过期，请重新登录。
- 网络连接失败，请稍后重试。
- 当前设备已被移除，请重新登录。
- 同步冲突，请先合并云端数据。

## 9. 推荐客户端文件边界

```text
src/api/auth.ts              # 账号、验证码、设备接口
src/api/sync.ts              # 同步状态、推送、拉取、合并、备份
src/store/useAuthStore.ts    # 登录会话
src/store/useSettingsStore.ts# 同步开关和服务器配置
src/utils/syncError.ts       # 技术错误转换为用户文案
src/App.tsx                  # 自动同步生命周期
src/pages/ProfilePage.tsx    # 账号、验证、设备、同步入口
```

同步逻辑必须集中在 API/store/生命周期层，避免散落到任务、日历、目标等页面中。
