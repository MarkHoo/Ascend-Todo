# 目标功能设计文档

## 1. 全局数据模型与数据库设计 (Database Schema)

### 1.1 目标表 (goals)

记录用户设定的主目标（Objective）。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BigInt | PK, Auto Increment | 主键 ID |
| `user_id` | BigInt | FK, Index | 用户 ID |
| `title` | Varchar(255) | Not Null | 目标名称（如：精通 Flutter 开发） |
| `description` | Text | Nullable | 动机与背景描述 |
| `dimension` | Enum | Not Null | 维度：`HEALTH`(健康), `CAREER`(职业), `FINANCE`(财务), `LEARNING`(学习), `LIFE`(生活) |
| `start_date` | Date | Not Null | 周期开始日期 |
| `end_date` | Date | Not Null | 周期结束日期 |
| `status` | Enum | Default: `ACTIVE` | 状态：`ACTIVE`(进行中), `COMPLETED`(已达成), `DROPPED`(已放弃) |
| `progress` | Decimal(5,2) | Default: 0.00 | 目标整体进度（0.00 - 100.00） |
| `score` | TinyInt | Nullable | 周期结束自我评分（0 - 10） |
| `review_note` | Text | Nullable | 周期复盘总结 |
| `created_at` | Timestamp | Not Null | 创建时间 |
| `updated_at` | Timestamp | Not Null | 更新时间 |

### 1.2 关键结果表 (key_results)

记录定量衡量目标的指标（Key Result）。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BigInt | PK, Auto Increment | 主键 ID |
| `goal_id` | BigInt | FK, Index | 关联的目标 ID |
| `title` | Varchar(255) | Not Null | KR 描述（如：阅读 5 本技术书籍） |
| `type` | Enum | Not Null | 类型：`METRIC`(数值型), `BOOLEAN`(里程碑型) |
| `start_value` | Decimal(10,2) | Default: 0.00 | 初始值（仅 METRIC 有效） |
| `target_value` | Decimal(10,2) | Default: 1.00 | 目标值（METRIC 为具体数，BOOLEAN 默认为 1.00） |
| `current_value` | Decimal(10,2) | Default: 0.00 | 当前实际值 |
| `unit` | Varchar(50) | Nullable | 单位（如：本, kg, 元） |
| `progress` | Decimal(5,2) | Default: 0.00 | 单项 KR 进度（0.00 - 100.00） |

### 1.3 任务表 (tasks)

日常待办事项（Todo），可独立存在，也可关联目标。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BigInt | PK, Auto Increment | 主键 ID |
| `user_id` | BigInt | FK, Index | 用户 ID |
| `goal_id` | BigInt | FK, Index, Nullable | 关联目标 ID（允许为空） |
| `kr_id` | BigInt | FK, Index, Nullable | 关联关键结果 ID（允许为空） |
| `title` | Varchar(255) | Not Null | 任务内容 |
| `is_completed` | Boolean | Default: false | 是否完成 |
| `due_date` | Date | Nullable | 截止日期 |
| `completed_at` | Timestamp | Nullable | 完成时间 |

### 1.4 进度流水表 (progress_logs)

记录 KR 的更新历史，用于生成趋势图。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | BigInt | PK, Auto Increment | 主键 ID |
| `kr_id` | BigInt | FK, Index | 关键结果 ID |
| `old_value` | Decimal(10,2) | Not Null | 更新前数值 |
| `new_value` | Decimal(10,2) | Not Null | 更新后数值 |
| `comment` | Varchar(500) | Nullable | 更新时填写的进展备注 |
| `created_at` | Timestamp | Not Null | 记录时间（签到时间） |

## 2. 核心算法与业务逻辑 (Core Logic)

### 2.1 进度计算规则

#### 2.1.1 关键结果（KR）进度计算

* **METRIC (数值型)**:

$$KR_{progress} = \frac{current\_value - start\_value}{target\_value - start\_value} \times 100\%$$



*(注：若计算结果 $> 100\%$，封顶显示为 $100.00\%$；若计算结果 $< 0\%$，触底显示为 $0.00\%$)*
* **BOOLEAN (里程碑型)**:
* `current_value` 仅支持 `0.00` (未完成) 或 `1.00` (已完成)。
* 对应进度为 `0.00%` 或 `100.00%`。



#### 2.1.2 目标（O）进度计算

主目标的进度由其下属所有关键结果（KR）的进度取**算术平均值**决定。设某个目标下有 $n$ 个 KR：


$$Goal_{progress} = \frac{1}{n} \sum_{i=1}^{n} KR_{progress\_i}$$

### 2.2 触发联动逻辑

当用户在“任务表”或“进度流水表”中发生操作时，系统需自动执行以下数据库联动（事务处理）：

```
[操作: 更新 KR 当前值 / 提交 Check-in] 
       │
       ▼
[更新 key_results.current_value] ──> [重新计算该 key_results.progress]
                                                 │
                                                 ▼
[重新计算 goals.progress (基于所有属下 KR 均值)] ──> [更新 goals 表]

```

* **任务勾选联动（可选通路）**：
若任务 `tasks` 关联了类型为 `METRIC` 且单位为“次/本/个”等计数的 `kr_id`，当 `tasks.is_completed` 由 `false` 变更为 `true` 时，系统自动将对应的 `key_results.current_value` 加 `1.00`。反之取消勾选则减 `1.00`。

## 3. 功能模块规格说明 (Functional Specifications)

### 3.1 目标库模块 (Goal Management)

#### 3.1.1 创建目标 (Create Goal)

* **输入校验**：
* `title` 不能为空，长度 $\le 255$ 字符。
* `start_date` 必须 $\le$ `end_date`。
* 一个目标必须包含至少 1 个、至多 5 个 KR。


* **业务规则**：创建目标时，必须同步在单个事务中写入 `key_results` 表。

#### 3.1.2 更新/打卡 (Check-in KR)

* **接口行为**：POST `/api/v1/kr/check-in`
* **请求参数**：`{ kr_id: Long, new_value: Decimal, comment: String }`
* **处理逻辑**：
1. 查询原 `current_value` 赋值给 `old_value`。
2. 写入 `progress_logs` 表。
3. 更新 `key_results.current_value` 并级联计算更新 `goals.progress`。



#### 3.1.3 结项与复盘 (Archive & Review)

* **触发条件**：当前系统日期 $>$ `goals.end_date` 或用户手动点击“结束目标”。
* **操作控制**：
* 状态修改为 `COMPLETED` 或 `DROPPED`。
* 该目标及其所属 KR 变更为**只读状态**，前端隐藏“更新/打卡”按钮，仅保留 `score` 和 `review_note` 的编辑权限。



### 3.2 待办清单模块 (Task/Action Management)

#### 3.2.1 任务列表加载

* **过滤逻辑**：
* **今日聚焦视图**：查询 `tasks` 表中 `user_id = 当前用户 AND is_completed = false AND goal_id IS NOT NULL`，并按 `due_date` 升序排列。
* **常规无关联视图**：查询 `goal_id IS NULL` 的日常杂务。



#### 3.2.2 关联关系建立

* **前端交互**：在创建/编辑 Task 弹窗中，下拉异步加载当前用户所有 `status = 'ACTIVE'` 的目标及其对应的 KR 列表。
* **数据注入**：选中后，写入 `tasks.goal_id` 和 `tasks.kr_id`。

## 4. 界面状态与视觉逻辑 (UI/UX Logic)

### 4.1 进度条颜色状态机 (Progress Color Rules)

前端根据目标/KR 的当前进度及时间消耗比例，动态渲染进度条颜色：

* **计算时间消耗率**：

$$Time_{elapsed} = \frac{CurrentDate - start\_date}{end\_date - start\_date} \times 100\%$$


* **颜色状态映射表**：

| 条件判定 | 状态 | 前端 UI 颜色代码 (推荐) |
| --- | --- | --- |
| $Progress \ge Time_{elapsed}$ | 正常/领跑 | 绿色 (`#52C41A`) |
| $Time_{elapsed} - Progress \le 20\%$ | 轻度滞后 | 黄色 (`#FAAD14`) |
| $Time_{elapsed} - Progress > 20\%$ | 严重滞后/风险 | 红色 (`#F5222D`) |

### 4.2 数据可视化要求

* **热力图 (Heatmap)**：按后端返回的 `v1/stats/heatmap` 接口数据（按天聚合已完成的任务数量），渲染类似 GitHub 贡献图的 365 天方块格子。
* **趋势图 (Trend Chart)**：点击 KR 详情时，基于 `progress_logs` 的 `created_at`（X轴）和 `new_value`（Y轴）绘制折线图。

## 5. 非功能性需求 (Non-Functional Requirements)

* **性能指标**：打卡/更新进度接口响应时间（RT）必须 $< 200\text{ms}$（包含级联计算与事务提交时间）。
* **离线支持**：前端涉及存储草稿或今日待办勾选时，需支持本地存储（如 IndexedDB / SQLite），网络恢复后通过时间戳进行双向同步（增量同步）。
