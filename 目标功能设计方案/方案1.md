# 目标功能设计文档

## 1. 产品概述
### 1.1 产品定位
OKR（目标与关键结果）管理与执行工具。将企业级OKR方法论降维应用于个人成长，结合**任务看板、甘特图、数据仪表盘**等执行视图，帮助个人实现“目标设定-任务拆解-进度追踪-复盘洞察”的闭环管理。

### 1.2 核心业务流
`设定周期` ➔ `制定O与KR` ➔ `拆解为看板任务/甘特图排期` ➔ `日常打卡与进度更新` ➔ `周期复盘与数据归档`

---

## 2. 全局说明
### 2.1 核心概念定义
| 概念 | 定义 | 个人场景示例 |
| :--- | :--- | :--- |
| **周期 (Cycle)** | OKR执行的时间窗口 | 2026年Q2、2026年6月 |
| **目标 (Objective)** | 定性、鼓舞人心的方向 | 提升个人英语商务沟通能力 |
| **关键结果 (KR)** | 定量、衡量O是否达成的指标 | 1. 背诵2000个商务词汇；2. 完成3次全英文模拟面试 |
| **行动 (Task)** | 为达成KR而拆解的具体待办 | 每天晚上用App背50个单词 |

### 2.2 全局状态说明
- **OKR状态**：`草稿` ➔ `进行中` ➔ `已复盘` ➔ `已归档`
- **KR状态**：`未开始` ➔ `进行中` ➔ `有风险`(进度滞后) ➔ `已完成`
- **任务状态**：`待办` ➔ `进行中` ➔ `已完成`

## 3. 核心功能模块设计

### 3.1 OKR 管理模块 (核心设定)
**功能目标**：提供结构化的目标设定界面，支持多维度指标定义。

#### 3.1.1 周期管理
- **交互逻辑**：顶部全局切换器，支持按“年度 / 季度 / 月度 / 自定义”切换当前工作区。
- **数据过滤**：切换周期后，下方所有视图（看板、甘特图、仪表盘）仅展示该周期内的数据。

#### 3.1.2 O (目标) 创建与编辑
- **字段设计**：
  - `目标名称` (必填，限50字)
  - `目标描述` (选填，富文本，记录初衷)
  - `权重` (选填，1-5星，用于计算整体进度)
  - `标签` (如：健康、职业、财务、学习)
- **交互说明**：采用卡片式折叠面板，展开后显示关联的KR列表。

#### 3.1.3 KR (关键结果) 设定
支持三种KR类型，系统根据类型自动计算进度：
| KR类型 | 字段配置 | 进度计算逻辑 | 示例 |
| :--- | :--- | :--- | :--- |
| **数值型** | 起始值、目标值、单位 | `(当前值-起始值)/(目标值-起始值)*100%` | 存款从0到50,000元 |
| **百分比型** | 目标百分比 | `当前百分比/目标百分比*100%` | 体脂率降至15% |
| **里程碑型** | 子节点列表 (Checklist) | `已完成子节点数/总子节点数*100%` | 考取PMP证书(报名/学习/考试) |

---

### 3.2 执行视图模块 (过程管理)
**功能目标**：将高维度的KR落地为日常可执行的动作，提供多视角的管理工具。

#### 3.2.1 任务看板 (Task Board)
- **功能描述**：将KR拆解为具体的Task，通过看板进行敏捷管理。
- **默认分组**：`待办 (To Do)` | `进行中 (Doing)` | `阻塞/等待 (Blocked)` | `已完成 (Done)`
- **卡片信息展示**：
  - 任务标题、截止日期
  - 关联的KR标签（点击可跳转至对应OKR）
  - 优先级标识（P0/P1/P2）
- **交互操作**：支持拖拽卡片跨列移动，自动更新任务状态；支持双击卡片快速编辑。

#### 3.2.2 个人甘特图 (Gantt Chart)
- **功能描述**：以时间轴视角规划KR和核心任务的排期，避免个人时间冲突。
- **层级展示**：
  - 一级：Objective
  - 二级：Key Result
  - 三级：核心 Task
- **核心交互**：
  - **拖拽排期**：拖动任务条边缘调整起止时间。
  - **依赖关系**：支持连线设置前置任务（如：Task B必须在Task A完成后开始）。
  - **里程碑标记**：在时间轴上打菱形标记，代表KR的验收节点。

#### 3.2.3 数据表格 (Table View)
- **功能描述**：提供类似Excel的扁平化视图，适合批量管理和数据核对。
- **支持字段**：O名称、KR名称、当前值、目标值、进度%、状态、负责人(仅自己)、截止日期。
- **交互操作**：支持直接在单元格内修改数值（如更新KR当前值），系统自动触发进度重算并记录更新日志。

---

### 3.3 数据仪表盘 (洞察与复盘)
**功能目标**：通过数据可视化，提供个人效能洞察，辅助周期复盘。

#### 3.3.1 核心指标卡片 (KPI Cards)
- **本期OKR完成率**：所有O的加权平均进度。
- **KR达成率**：已完成KR数 / 总KR数。
- **任务履约率**：按时完成的任务数 / 总任务数。
- **专注度指数**：基于每日打卡和任务推进频率计算的活跃度评分。

#### 3.3.2 可视化图表
| 图表名称 | 展示维度 | 业务价值 |
| :--- | :--- | :--- |
| **燃尽图 (Burn-down)** | 剩余任务量 vs 时间 | 监控当前周期执行节奏是否健康 |
| **雷达图 (Radar)** | 各标签(健康/学习等)的投入占比 | 发现个人精力分配是否失衡 |
| **趋势折线图** | 历史周期的OKR得分走势 | 追踪个人长期成长轨迹 |

#### 3.3.3 周期复盘向导
- **触发时机**：周期结束前3天，或用户手动点击“开始复盘”。
- **复盘表单**：
  1. **打分**：对本周期O的达成情况进行0.1-1.0的自评打分。
  2. **灵魂三问**（文本域）：
     - 哪些做法被证明是有效的？
     - 哪些地方遇到了阻碍，原因是什么？
     - 下个周期需要保留或改变什么？
- **归档逻辑**：提交复盘后，当前周期数据锁定并归档，自动生成历史快照。

## 4. 数据模型与状态机设计

### 4.1 核心实体关系 (ER)
```text
[Cycle] 1 : N [Objective]
[Objective] 1 : N [KeyResult]
[KeyResult] 1 : N [Task]
[Task] N : N [Task] (依赖关系)
```

### 4.2 核心字段字典 (供开发建表参考)

**表：`key_results`**
| 字段名 | 类型 | 说明 | 约束 |
| :--- | :--- | :--- | :--- |
| `id` | UUID | 主键 | |
| `objective_id` | UUID | 关联目标 | 外键 |
| `type` | ENUM | `numeric`, `percent`, `milestone` | 默认 `numeric` |
| `start_val` | DECIMAL | 起始值 | |
| `target_val` | DECIMAL | 目标值 | |
| `current_val` | DECIMAL | 当前值 | 触发器自动计算进度 |
| `status` | ENUM | 状态机定义 | |
| `updated_log` | JSON | 进度更新历史快照 | 记录时间戳和变更值 |

### 4.3 进度计算引擎逻辑 (伪代码)
```javascript
// 当 current_val 更新时触发
function calculateProgress(kr) {
    if (kr.type === 'milestone') {
        return (kr.completed_milestones / kr.total_milestones) * 100;
    }
    let progress = ((kr.current_val - kr.start_val) / (kr.target_val - kr.start_val)) * 100;
    return Math.max(0, Math.min(100, progress)); // 限制在0-100%之间
}

// 目标(Objective)进度计算
function calculateObjectiveProgress(objective) {
    let totalWeight = sum(kr.weight);
    let weightedSum = sum(kr.progress * kr.weight);
    return weightedSum / totalWeight;
}
```

## 5. 异常与边界处理规范

1. **进度倒退处理**：允许用户将KR当前值改小（如：体重反弹、存款减少），系统需记录负向更新日志，并在仪表盘中以红色警示标记。
2. **周期跨越**：若周期结束时KR未完成，提供两个选项：`标记为失败并归档` 或 `一键迁移至下一周期`（保留原设定值，重置当前值）。
3. **数据删除保护**：已关联Task的KR不允许直接删除，需先解除关联或级联删除（需二次弹窗强提示）。
4. **离线支持**：看板和表格视图支持本地缓存，断网状态下可拖拽任务和修改数值，网络恢复后通过时间戳比对解决冲突并同步。
