# 目标功能设计文档

## 1. 产品定义

帮助用户设定量化目标、跟踪关键结果进度、通过数据反馈提升执行力。核心解决「目标模糊、执行松散、反馈滞后」三个痛点。

---

## 2. 核心功能架构

```
目标管理
├── 目标（Objective）：定性描述，设定周期与分类
├── 关键结果（Key Result）：3-5个量化指标，含权重
├── 进度更新（Check-in）：更新当前值，记录日志
├── 数据分析（Insight）：完成度、趋势、习惯强度
└── 激励反馈（Feedback）：成就、连续打卡、提醒
```

## 3. 功能模块详细设计

### 3.1 目标管理

#### 3.1.1 目标创建
**入口**：首页「+」按钮 / 目标列表页「新建目标」

**界面要素**：
| 字段 | 类型 | 必填 | 限制 |
|------|------|------|------|
| 目标标题 | 文本 | 是 | 30字以内 |
| 目标描述 | 多行文本 | 否 | 300字以内 |
| 目标分类 | 单选 | 是 | 学习成长/健康管理/职业发展/生活品质/财务管理/人际关系 |
| 周期类型 | 单选 | 是 | 月度/季度/半年度/年度/自定义 |
| 起止日期 | 日期选择 | 是 | 结束日期 > 开始日期 |
| 优先级 | 单选 | 否 | 高/中/低（默认中） |
| 标签 | 多选 | 否 | 自定义，最多5个 |
| 可见性 | 单选 | 否 | 仅自己（默认）/ 公开 |

**业务规则**：
- 创建时同步引导添加至少1个关键结果，否则目标为「草稿」状态
- 草稿状态不计入统计数据
- 同一周期内同分类下「进行中」目标建议不超过5个，超出时弹窗提示聚焦

#### 3.1.2 目标状态流转
```
草稿 → 进行中（添加首个KR后自动流转）
进行中 → 已完成（所有KR进度达100%）
进行中 → 已放弃（用户手动操作，需填写放弃原因）
进行中/已完成/已放弃 → 已归档（用户手动操作，归档后不可编辑，可恢复）
```

#### 3.1.3 目标列表
**视图模式**：卡片视图（默认）、看板视图（按状态分栏）

**筛选维度**：状态 / 分类 / 周期 / 优先级 / 标签

**排序方式**：最近更新 / 到期时间 / 完成度 / 创建时间

**卡片展示要素**：
- 标题（超过20字截断）
- 分类色标
- 环形进度图（整体完成度）
- 剩余天数（<<7天标红）
- 最近更新时间
- 快捷操作：更新进度 / 编辑 / 更多

### 3.2 关键结果（KR）

#### 3.2.1 KR设定
**界面要素**：
| 字段 | 类型 | 必填 | 限制 |
|------|------|------|------|
| KR标题 | 文本 | 是 | 80字以内 |
| 起始值 | 数字 | 否 | 默认0 |
| 当前值 | 数字 | 否 | 默认等于起始值 |
| 目标值 | 数字 | 是 | 必须 ≠ 起始值 |
| 单位 | 文本 | 否 | 如：个、次、kg、km、% |
| 权重 | 数字 | 是 | 1-100，同一目标下所有KR权重之和必须=100 |
| 难度 | 单选 | 否 | 简单/适中（默认）/困难 |

**业务规则**：
- 目标下KR数量限制：最少1个，最多5个
- 权重自动分配：新增KR时默认均分权重，用户可手动调整
- 难度影响成就系数：困难KR完成获得更高积分

#### 3.2.2 进度更新
**更新方式**：
1. **精确输入**：输入具体数值，系统自动计算百分比
2. **百分比滑块**：0%-100%滑动
3. **快速+1**：针对计数型KR（如阅读次数），点击+1递增

**更新日志**：
- 每次更新必须记录时间戳
- 可选填写文字备注（140字以内）
- 可选上传图片（最多3张，单张<<5MB）

**业务规则**：
- 当前值允许超过目标值（超量完成），但完成度上限为100%
- 支持修改历史记录，修改后重新计算该时间点的完成度
- 连续7天未更新的「进行中」目标，系统标记「需关注」

- 中断后重新计算

## 5. 核心流程

### 5.1 创建目标并跟踪流程
```
用户点击「新建目标」
    ↓
填写目标信息（标题、分类、周期）
    ↓
引导添加KR（至少1个）
    ↓
设定KR量化指标（起始值、目标值、单位、权重）
    ↓
目标状态变为「进行中」
    ↓
用户在首页/详情页点击「更新进度」
    ↓
输入当前值或调整百分比
    ↓
系统实时计算并更新整体完成度
    ↓
记录进度日志
    ↓
触发成就检测
    ↓
若整体完成度达100%，目标状态变为「已完成」
```

### 5.2 目标完成度计算流程
```
获取目标下所有KR
    ↓
对每个KR：
    完成度 = (当前值 - 起始值) / (目标值 - 起始值) × 100%
    若完成度 < 0，取0；若 > 100，取100
    加权完成度 = 完成度 × 权重
    ↓
目标整体完成度 = Σ(加权完成度) / Σ(权重)
    ↓
四舍五入保留1位小数
```

## 7. 核心业务规则

### 7.1 完成度计算
```javascript
function calculateObjectiveProgress(objectiveId) {
    const krs = getKeyResults(objectiveId);
    let weightedSum = 0;
    let totalWeight = 0;
    
    for (const kr of krs) {
        const range = kr.targetValue - kr.startValue;
        if (range === 0) continue; // 避免除零
        
        let progress = (kr.currentValue - kr.startValue) / range * 100;
        progress = Math.max(0, Math.min(100, progress));
        
        weightedSum += progress * kr.weight;
        totalWeight += kr.weight;
    }
    
    return totalWeight > 0 ? 
        Math.round((weightedSum / totalWeight) * 10) / 10 : 0;
}
```

### 7.2 连续打卡天数计算
```javascript
function calculateStreak(userId, krId) {
    const checks = getHabitChecks(userId, krId)
        .sort((a, b) => b.check_date - a.check_date);
    
    let streak = 0;
    let expectedDate = new Date(); // 今天
    
    for (const check of checks) {
        if (isSameDay(check.check_date, expectedDate)) {
            streak++;
            expectedDate.setDate(expectedDate.getDate() - 1);
        } else if (isBefore(check.check_date, expectedDate)) {
            break; // 出现空缺，中断
        }
    }
    return streak;
}
```

### 7.3 提醒触发逻辑
```javascript
function shouldRemind(objective) {
    // 规则1：每日提醒
    const lastUpdate = getLastUpdateTime(objective.id);
    const now = new Date();
    if (daysDiff(lastUpdate, now) >= 1 && now >= objective.user.reminderTime) {
        return true;
    }
    
    // 规则2：到期预警
    const daysUntilEnd = daysDiff(now, objective.endDate);
    if (daysUntilEnd <= 3 && daysUntilEnd >= 0 && objective.status === 'active') {
        return true;
    }
    
    // 规则3：长期未更新
    if (daysDiff(lastUpdate, now) >= 3 && objective.status === 'active') {
        return true;
    }
    
    return false;
}
```

### 7.4 目标状态自动流转
- **草稿→进行中**：添加首个KR后自动触发
- **进行中→已完成**：整体完成度首次达到100%时自动触发，同时推送通知
- **已完成→进行中**：用户手动回退，允许继续更新进度
- **任意状态→已归档**：仅用户手动操作，归档后所有KR锁定不可编辑

## 8. 异常处理

| 异常场景 | 系统行为 |
|---------|---------|
| 目标到期时完成度<<100% | 状态保持「进行中」，用户可手动标记「已完成」或「已放弃」 |
| KR目标值设为0 | 保存时校验报错：「目标值不能等于起始值」 |
| 权重总和≠100% | 保存时校验报错，自动提示调整 |
| 用户连续30天未登录 | 暂停推送通知，用户再次登录时恢复 |
| 图片上传失败 | 允许保存进度记录，图片标记为「上传失败」，支持重新上传 |
| 网络异常导致更新失败 | 本地缓存数据，网络恢复后自动重试，冲突时以服务端为准 |
